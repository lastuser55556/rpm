# Сложность алгоритмов

Считаю число проверенных элементов. Оба поиска запускаются на одинаковом отсортированном массиве и ищут отсутствующее значение, превышающее все элементы. Результаты запуска находятся в [results.txt](results.txt).

| Порядок роста | Пример |
|---|---|
| O(1) | Чтение элемента массива по индексу |
| O(log n) | Двоичный поиск |
| O(n) | Линейный поиск |
| O(n log n) | Сортировка слиянием |
| O(n²) | Проверка всех пар |
| O(2ⁿ) | Перебор всех подмножеств |

Линейный поиск работает на любом массиве. Двоичный поиск требует отсортированных данных. Если массив уже отсортирован, увеличение размера в 10 раз добавляет примерно 3–4 проверки. При разовом поиске цену предварительной сортировки нужно учитывать отдельно. Дополнительная память обеих реализаций — O(1).

P содержит задачи принятия решения, разрешимые за полиномиальное время. В NP входят задачи принятия решения, для которых положительный ответ имеет полиномиально проверяемый сертификат. Например, для SAT можно проверить присваивание значений переменным. SAT — NP-полная задача, и вопрос P = NP остаётся открытым. Неразрешимость — другой случай: для задачи остановки алгоритм, правильно отвечающий на всех программах и входах, не существует.

Запуск: `python3 main.py`.
